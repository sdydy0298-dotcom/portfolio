## 콘텐츠 관리

- `index.html`: 사진·소개·경력·기술·학력·자격증
- `app.js`의 `compact`: 프로젝트 요약과 짧은 구축·문제 해결 기록
- `content.json`: 공개 프로젝트 ID·제목·서비스 사진·토폴로지 목록
- `assets/`: 프로필·프로젝트 이미지
- `styles.css`: 두 페이지 레이아웃과 반응형·인쇄 스타일

기존 Supabase 상세 원문은 보존합니다. 빌드 시 기존 공개 레코드의 제목을 조회한 뒤 브라우저에는 ID·제목·서비스 사진·토폴로지 목록만 출력합니다. 상세 원문·내부 주소 등은 정적 JSON에 포함하지 않습니다. 브라우저에 DB 키를 전달하지 않습니다.

**요약 전용 content.json을 DB 상세 원문 전체에 덮어쓰지 마세요.** `sync:sql` 스크립트도 요약 데이터의 전체 덮어쓰기를 차단합니다. 원문 편집은 기존 Supabase 레코드에서 수행합니다.

GitHub `main`의 변경을 기존 Vercel 프로젝트가 배포합니다. 기존 환경 변수 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`와 RLS 정책을 유지합니다.

팀원의 개인 정보와 내부 문서는 포함하지 않습니다. 팀 공통 성과와 본인 역할, 설계 목표와 실제 검증 결과는 구분합니다. DB·WAS 복제와 운영 서비스 통합 검증은 진행 중 범위로 표시합니다.
